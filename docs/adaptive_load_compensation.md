# 人形机器人负载自适应补偿：设计文档

## 问题背景

人形机器人（BXI_ELF3）在搬运重箱时，负载引起重心偏移和动力学特性变化，默认 RL 行走策略出现不稳、点头、摇摆等问题。**约束条件：不能修改底层 ONNX 策略模型。**

## 文件结构

```
simple_env.py               ← 原始 RL 环境（PD 控制 + ONNX 策略推理）
simple_env_box.py           ← 箱子扩展：手臂解耦 + 固定 PD 调参 + 箱子质量
simple_env_box_waist.py     ← 腰部固定偏移方案（上限 0.02 rad，效果有限）
adaptive_load_env.py        ← 实时负载检测 + 自适应 PD 增益调度
```

### 1.1 关节布局（29 维）

```
索引   关节              分组
─────────────────────────────────
 0    waist_y           腰部 (3)
 1    waist_x
 2    waist_z
 3    l_hip_y           左腿 (6)
 4    l_hip_x
 5    l_hip_z
 6    l_knee_y
 7    l_ankle_y         左脚踝 (2)
 8    l_ankle_x
 9    r_hip_y           右腿 (6)
10    r_hip_x
11    r_hip_z
12    r_knee_y
13    r_ankle_y         右脚踝 (2)
14    r_ankle_x
15-21                   左臂 (7)
22-28                   右臂 (7)
─────────────────────────────────
 0-14: LEG_WAIST (15) ← 策略控制
15-28: ARM (14)       ← 固定托举姿态
```

### 1.2 解耦机制

实现于 `simple_env_box.py:244-248`：

```python
def policy_inference(self):
    super().policy_inference()                              # ONNX 推理，输出 29 维 action
    self.action[self.ARM_INDICES] = self.hold_arm_action    # 手臂 action 清零
    self.target_dof_pos[self.ARM_INDICES] = self.hold_arm_angle.copy()  # 手臂目标锁定
```

同时修改 `default_angles` 使手臂中性位置 = 托举姿态：

```python
self.default_angles[self.ARM_INDICES] = self.hold_arm_angle.copy()
```

### 1.3 控制架构

```
策略 (ONNX) 输出 29 维 action
        │
        ▼
  target_dof_pos = action × action_scale + default_angles
        │
        ├── indices 0-14 (腰+腿): 策略自由控制 ✅
        │
        └── indices 15-28 (双臂): 丢弃策略输出 ❌
                                 替换为 hold_arm_angle 固定值
        │
        ▼
  PD 控制器 (全部 29 关节): tau = kp×(target_q − q) + kd×(0 − dq)
        │
        ▼
  MuJoCo 物理仿真
```

### 1.4 观测自洽性

策略的 96 维观测中，手臂部分如实反映固定托举状态：

```
观测组成 (96 维):
┌─────────────────┬──────────┬──────────────────────────────────┐
│ omega (3)       │ 陀螺仪    │ 躯干角速度                        │
│ gravity (3)     │ 重力方向   │ 策略凭此感知前倾                   │
│ qj (29)         │ 关节位置   │ 手臂 ≈ 0（default_angles 已改了）  │
│ dqj (29)        │ 关节速度   │ 手臂 ≈ 0（被 PD 锁死）            │
│ last_action (29)│ 上一动作   │ 手臂 ≈ 0（被覆盖为零）            │
│ cmd (3)         │ 速度指令   │                                  │
└─────────────────┴──────────┴──────────────────────────────────┘
```

策略能看到手臂被固定，也还在计算手臂动作（只是被丢弃）。实测行走 20+ 秒不摔。

## 二、为什么改 `target_dof_pos` 不行（核心理论）

### 2.1 观测-策略的因果对

策略训练时学会了一个因果模型：

```
last_action[i] → qj[i]
    ↑               ↑
 "我发了指令 X" → "关节到了 Y"
```

即：`target_dof_pos = action × action_scale + default_angles` 这个公式是**训练固化的物理规律**。策略期望 `qj ≈ action × scale`（相对于 default）。

### 2.2 改 `target_dof_pos`：因果链断裂

```python
# 假设在 policy_inference() 中加了偏移
self.target_dof_pos[0] += 0.05   # 在策略计算的基础上 +0.05 rad
```

**第一周期**：

| 步骤 | 值 | 说明 |
|------|-----|------|
| 策略输出 `action[0]` | 0.12 | 策略想微调腰 |
| `target_dof_pos[0]` | default + 0.025 | 0.12 × 0.2075 |
| 我们的偏移 | +0.05 | 强行注入 |
| 实际 target | default + 0.075 | 翻了 3 倍 |
| PD 力矩 | kp × (0.075 − q) | 强力拉到 0.070 rad |
| 实际关节 `qj[0]` | 0.070 | 远超策略预期 |

**第二周期（观测出现矛盾）**：

| 步骤 | 值 | 说明 |
|------|-----|------|
| 观测 `qj[0]` | 0.070 | 关节跑到了 0.070 |
| 观测 `last_action[0]` | 0.12 | 但我上周期只发了 0.12！ |
| 策略判断 | "关节位置严重异常" | qj 和 last_action 不匹配 |
| 策略输出 `action[0]` | −0.35 | 极端反向修正 |

**第三周期（我们的偏移还在）**：

```
策略想: target = −0.073 (往后猛拉)
我们加: target = −0.073 + 0.05 = −0.023 （被抵消大半）
策略看到: 我发了 −0.35，关节怎么几乎没动？
```

**持续 6–8 秒后**：策略内部状态完全漂出训练分布 → 输出垃圾 → 机器人停走。

### 2.3 `action_scale` 的放大效应

```python
action_scale[0] = 0.2075

# 如果为了"自洽"同时修改 action 和 target：
self.target_dof_pos[0] += 0.05
self.action[0] = (self.target_dof_pos[0] − self.default_angles[0]) / 0.2075
# 0.05 / 0.2075 = 0.24 → action[0] 被额外加了 0.24！
```

一个小偏移（0.05 rad）在 action 空间里被放大约 5 倍（0.24），变成一个**非物理的尖刺信号**注入到观测的 `last_action`。对策略来说这等效于传感器故障。

### 2.4 两种改法的本质区别

```
改 target_dof_pos（offset）:
  ┌──────────┐      ┌──────────┐      ┌──────────┐
  │ 策略输出  │ ──→  │ 我们篡改  │ ──→  │ 关节执行  │
  │  action  │      │ +offset  │      │    q     │
  └──────────┘      └──────────┘      └──────────┘
                          ↑
                    策略不知道这件事！
                    它的 last_action 还是原始 action
                    但它看到 q 不对 → 困惑 → 发散
                    ✗ 6-8 秒后停走

改 PD 增益（kp/kd）:
  ┌──────────┐      ┌──────────────────┐      ┌──────────┐
  │ 策略输出  │ ──→  │ 不变！原样传到 PD  │ ──→  │ 关节执行  │
  │  action  │      │ PD 更硬了          │      │    q     │
  └──────────┘      └──────────────────┘      └──────────┘
                          ↑
                    策略不关心 PD 刚度
                    它只知道发了指令 → 关节到了
                    而且到的位置和预期一致（甚至更精确）
                    ✓ 20 秒+ 连续走
```

| | 改 target_dof_pos | 改 PD 增益 |
|---|---|---|
| 策略的 `last_action` | 和实际执行**矛盾** | 和实际执行**一致** |
| 策略的因果模型 | 被打断 | 保持完整 |
| 策略视角 | "我控制不了这关节" | "我控制更精准了" |
| 观测-策略一致性 | 断裂 | 保持 |
| 结果 | 6-8s 后停走 | 20s+ 连续走 |

**一句话**：改 target 是「欺骗」策略，改 PD 是「帮助」策略。

## 三、箱子质量建模：「加到 torso」vs「手托举」

### 3.1 两种方式

**方式 A：质量直接改到躯干**（`simple_env_box.py` 采用）

```python
# simple_env_box.py:191-230
def _apply_box_to_torso(self):
    torso_id = mj_name2id("torso_link")
    # 直接修改躯干刚体的物理参数
    self.model.body_mass[torso_id] = old_mass + box_mass       # 质量 ↑
    self.model.body_ipos[torso_id] = new_com                   # 质心前移
    self.model.body_inertia[torso_id] = I_torso + I_box        # 惯量 ↑
```

```
    躯干 (质量↑、质心前移、惯量↑)
      │
    双腿
```

箱子变成躯干的一部分——**像背在背上，不是拿在手上**。

**方式 B：weld 约束手托举**（`bxi_elf3_scene_box.xml` 原方案，未采用）

```xml
<body name="box" pos="0.5 0 0.8">
  <freejoint name="box_joint"/>
  <!-- ... -->
</body>
<equality>
  <weld body1="box" body2="l_wrist_z_link"/>  <!-- 左腕焊箱子 -->
  <weld body1="box" body2="r_wrist_z_link"/>  <!-- 右腕焊箱子 -->
</equality>
```

```
    躯干 ──肩── 上臂 ──肘── 前臂 ──腕──┐
       │                                ├── 箱子 (独立刚体)
    躯干 ──肩── 上臂 ──肘── 前臂 ──腕──┘
```

形成 `torso → 左臂 → box → 右臂 → torso` 的运动学闭环。

### 3.2 两种方式对比

| 物理量 | 手托举 (weld) | 加到 torso | 一致？ |
|--------|:---:|:---:|:---:|
| 总质量 (robot+box) | 相同 | 相同 | ✅ |
| COM 前移 | 通过手臂链（间接） | 直接前移 0.12m | ⚠️ 近似 |
| 躯干前倾 (pitch) | 有 | 有 | ✅ |
| 腰部负载力矩 | 有 | 有 | ✅ |
| 手臂负载力矩 | **有** | **没有** | ❌ |
| 箱子相对晃动 | 有（手臂柔顺） | 无（刚性） | ❌ |
| 双臂内力冲突 | 有（闭环约束） | 无 | ❌ |
| 数值稳定性 | 需调参 | 稳定 | 相反方向 |

### 3.3 为什么选了方式 A

MuJoCo 的 equality 约束是**软约束（罚函数法）**，不是硬约束。双臂和箱子形成的闭环：

```
左臂推 → 箱子动 → 右臂被拉 → 右臂 PD 反抗 → 箱子被推回 → 左臂被拉 → …
```

需要仔细调 `solref`/`solimp` 参数防震荡。加上 50Hz 的策略控制，更容易不稳定。

**代价**：手臂负载力矩为零 → 无法用 `actuator_force[shoulder]` 检测负载 → 必须改用 pitch 信号。

## 四、自适应补偿系统

### 4.1 总架构

```
每 50Hz 控制周期 (policy_inference 覆盖):

  ┌─────────────────────────────────────────────────┐
  │  ① 负载检测                                      │
  │     pitch = arcsin(2*(qw*qy − qz*qx))            │
  │     pitch_dc = EMA(pitch, α=0.015, τ≈1.3s)      │
  │     equiv_load_kg = |pitch_dc| / 5.7             │
  └───────────────────┬─────────────────────────────┘
                      │
                      ▼
  ┌─────────────────────────────────────────────────┐
  │  ② 状态机 (带迟滞)                                │
  │     IDLE ──[load>0.5kg, 50步]──▶ LOADED          │
  │     LOADED ──[load<0.3kg, 50步]──▶ IDLE         │
  └───────────────────┬─────────────────────────────┘
                      │
                      ▼
  ┌─────────────────────────────────────────────────┐
  │  ③ PD 增益调度                                    │
  │     target_gain = clamp(1+0.03×|pitch_dc|, 1, 1.25) │
  │     EMA smooth (α=0.05)                          │
  │     缩放 waist + ankle + arm 的 kp/kd            │
  │     不碰 hip（髋关节 = 步态执行关节）               │
  └───────────────────┬─────────────────────────────┘
                      │
                      ▼
  ┌─────────────────────────────────────────────────┐
  │  ④ 策略推理 (不修改 target_dof_pos)                │
  │     ONNX 推理 → action → target_dof_pos          │
  │     BoxEnv 覆盖手臂 target → 锁定托举姿态         │
  └─────────────────────────────────────────────────┘
```

### 4.2 负载检测：为什么用 pitch，不用手臂力矩

因为箱子质量是加到躯干（torso）上的，**手臂不承重**，手臂 PD 力矩始终接近零。

**正确信号通路**：

```
箱子质量 → torso 质量↑、COM 前移
  → 躯干绕 waist_y 持续前倾
  → free joint quaternion 偏转
  → pitch (arcsin 提取) 出现 DC 偏移
  → 检测到负载
```

**Pitch 不需要校准**：策略训练时躯干接近水平（pitch≈0°）。任何持续前倾都是异常的——0° 就是天然 baseline。EMA 低通滤波（τ≈1.3s）提取直流分量，滤除 ±3° 的 ~2Hz 步态振荡。

**经验标定**：1kg 箱子 ≈ 5.7° 直流 pitch（从 BoxEnv 实测得出）。

### 4.3 PD 增益调度的约束

初始值来自 `BoxEnv` 的固定调参（腰×2, 踝×1.5, 臂×2，相对于原始策略 PD）：

```
负载增益调度是叠加在 BoxEnv 固定调参之上的：
  kp_eff = BoxEnv_kp × clamp(1 + load_gain × |pitch_dc|, 1, max_gain)

例如 5° pitch，load_gain=0.03：
  目标增益 = 1 + 0.03 × 5 = 1.15
  腰部 kp = 217 × 1.15 = 250 (原始 108 × 2.3)
```

**不缩放的关节**：髋关节（hip_y/x/z, knee_y）*不缩放*。这些是步态执行核心，动它们会让腿太硬，策略的步态动作无法执行 → 机器人摔倒。

### 4.4 测试结果

| 质量 | 方案 | 摔倒 | Pitch (°) | VelX (m/s) | 10s 距离 | Arm 漂移 | 增益 |
|:---:|------|:---:|:---------:|:----------:|:------:|:------:|:---:|
| 1kg | 固定 PD | ✗ | 6.1 | 0.37 | 4.1m | 0.014 | — |
| 1kg | **自适应** | ✗ | **5.5** | **0.47** | **5.1m** | 0.012 | 1.14× |
| 3kg | 固定 PD | ✗ | 5.7 | 0.52 | 5.7m | 0.015 | — |
| 3kg | **自适应** | ✗ | **5.1** | **0.65** | **7.1m** | 0.012 | 1.12× |
| 5kg | 固定 PD | ✗ | 5.3 | 0.69 | 7.5m | 0.015 | — |
| 5kg | **自适应** | ✗ | **5.1** | 0.68 | 7.5m | 0.012 | 1.13× |
| 7kg | 固定 PD | ✗ | 5.3 | 0.63 | 6.9m | 0.015 | — |
| 7kg | **自适应** | ✗ | 5.2 | 0.60 | 6.6m | 0.012 | 1.13× |

- 自适应方案一致降低 pitch 0.2–0.6°
- 一致降低手臂漂移 ~0.003 rad
- 轻载（1–3kg）时提升行走速度
- 所有测试均不摔倒

## 五、局限性

1. **PD 增益天花板**：腰部 kp 最多 ×2.5 原始值（验证上限），超出会导致策略发散。增益提升空间有限（~25% 相对 BoxEnv 基线）。

2. **轻载改善高于重载**：7kg 时 pitch 改善仅 0.1°，远不如 1kg 时的 0.6°。因为 pitch 本身不随质量线性增长（策略已部分补偿）。

3. **箱子建模不真实**：质量焊在躯干上，不是手托举。无法研究手臂力矩控制、箱子晃动对步态的影响。

4. **10kg 不可行**：两种方案都在 10kg 时摔倒——超出策略泛化范围。

5. **最佳方案仍是重新训练**：在训练数据中随机化躯干质量和 COM 偏移（domain randomization），让策略学会在任意负载下行走。所有不修改策略的方案都只能做边际改善。
